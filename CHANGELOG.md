# Changelog

Notable changes to AgentFrame. Full release notes also live on the [GitHub releases page](https://github.com/situhacks/agentframe/releases).

## Unreleased

- The registers are the `.md` files in the voice folder's `registers/` directory, not a list in the code. `af voice bundle --register` and `--borrow` accept a name when its file exists and refuse any other, listing the registers that exist (a new `registers/slack.md` is usable at once, and `README.md` there is not a register). The default register is `informal` when it exists, else the first by name. A head whose `base_register` or `register` names a register with no file builds the default register and prints `register formal has no file; using informal`; a `borrow_from` entry with no file is dropped with a line saying so; exit 0, so old deliverables keep working. The refusal of an unknown register is now af's own (exit 1) rather than clap's usage error (exit 2). The voice schema and `voice-setup.md` describe `informal` and `chat` as the usual registers and `formal` as optional.

- `system/tools/harness_review.py` writes a harness review every 14 days, started by the morning batch run: words each chat loads at start, pages with items to fix, merged branches and clean worktrees, ended and orphaned session rows, skills, tools and process files nothing mentions, stale backlog rows, old scratch folders and the age of the model facts. It is read-only, raises one loop for main when it finds items, and its report lands in `system/logs/harness-review-<date>.md`.
- The `builder` agent no longer declares `isolation: worktree`, which the harness refused here and which started from an old commit; the caller makes the worktree from local master and names its path in the brief. The process cap for `AGENTS.builder.md` and `AGENTS.operator.md` reads 1,000 words, as the doctor enforces, and the skill table lives only in `.claude/skills/README.md`.

- `af voice bundle` loads on a scale of three tiers: `quick` (the anti-patterns, identity, the register and a short excerpt of about 400 words), `standard` (what `core` held; `--tier core` is now an alias of it) and `full`. A new `chat` register (`registers/chat.md`, for how he texts friends) works with `--register`, `--borrow` and a head's recipe, and a new `message` context (`chat` is the same) asks for `quick`. With no `--tier`, the context decides: a long-form, builder-pov, market-signal, slide or cover context gives `full`, message and chat alone give `quick`, a mix of email, short-form, message and chat gives `standard`, and no context gives `quick` for the chat register and `standard` for the others, where it used to give `full`. A register's own `pairs/{register}.md` is optional in `full`, the report says how the tier was chosen and prints one hint per other tier, and every tracked file that tells an agent how to load voice uses one wording.
- A needs-list decision keeps its recommendation, options and reason on its line in `open.md`, and `af needs add` no longer needs a file: `af needs add "<question>" --rec "<12 words or fewer>" [--option "<30 words or fewer, no ;>"]... [--why "<60 words or fewer>"] [--more <path[#anchor]>]` writes `· rec: … · options: a) …; b) … · why: … · more: …` between `need` and `from:` (up to 5 options, lettered by af; a value may not contain ` · `; `--more` must be an existing file, not under `workspace/life/needs/`). New `af needs set <n, slug, or text prefix>` changes only the fields named (`--option` replaces the list, an empty value clears one) and `--drop-detail` folds an old detail file into the line and moves the file to `needs/closed/` (it refuses unless the line has a `rec:`). `needs.md` has the columns `Decision | Recommendation | More` (`When` first in Later) and, under the Now and Later tables, a block per item that has options or a reason. `af needs list`, session start and `af brief` print the recommendation from the line. `af doctor` reports a field over its cap and a `more:` that is gone, and notes how many open items still keep an old detail file and the command that folds one in. Old-style lines (`· detail needs/<slug>.md`) still parse and work, `--detail` is still accepted with a note, and `loop_sweep.py` reads both shapes. The view escapes `<` and `>` and a leading list, heading or rule marker in what it prints from a line, so a reason cannot open an HTML comment or a heading in `needs.md`; `--drop-detail` prints where the file went, logs a `folded:` line, and changes nothing if the file cannot move; `--more` refuses a drive letter or other absolute path and drops `.` segments before its `needs/` check; `af brief --json` gives `more` as a vault-relative path.
- The session page. `system/sessions/<name>/handoff.md` is now the chat's page, what is current and nothing else: State (150 words or fewer), Doing, To do, Gated, Done, Rules, Open questions, Next step, Files touched, with dated one-line items, and an `archive.md` beside it that is never printed at session start. One function checks it and every issue is one of two kinds. `[fix]` issues block a stop: a body over 1,200 words, an unknown, missing or misordered heading, an item with no date, a Gated item with no `waits on:`, more than 10 Done items or one older than 14 days. `[review]` issues never block: a State over 150 words, a To do item over 21 days old, a Gated item over 45, a Rule over 30. A `## ` or `- ` line inside a fenced code block is plain text. New `af session tidy [<name>] [--check] [--all]` keeps the 10 newest Done items by date, moves the rest and any older than 14 days to the archive (each file replaced through a temp file, the archive first; an item already filed in its month is not filed twice, so a re-run after a crash is harmless) and prints the issues (exit 1 while any remains). The Stop hook blocks once on a `[fix]` issue after the staleness checks (never for `main`, never for a `[review]` issue); session start adds a block listing every issue (`af: your page needs tidying before other work:` when one is a `[fix]`, `af: your page has items to review when this task allows:` when none is) and prints an over-long page cut at a line end under 1,200 words with a line giving the words shown and the total; `af doctor` has a note per issue for every chat not ended and no longer counts `archive.md` when it judges a page stale; `af brief` calls a page that only needs tidying current. The missing-handoff message names only the required sections. A page with the four old sections is still valid. `session tidy` exiting 1 is not counted as a button refusal. `af` now runs on a thread with a 64 MB stack: in a debug build even an unknown verb needs about 950 to 1024 KB of the main thread's 1 MB on Windows, because clap builds the whole command tree, and the changes to `sessions.rs` tipped it over. A panic on that thread still ends the process with exit code 101, and a thread that cannot start prints one line to stderr and exits 1.
- A tenth subagent role, `desk` (Sonnet), runs the Claude panel for another chat: it starts a side chat from its brief with `af session start`, registers it, puts it in a group, sets its panel name, and compacts or archives chats. The main router's side-chat line now names it in place of handing the operator a prompt to paste.
- `af session group list|create|rename|delete|add|remove` manages the panel's session groups, through new driver actions `groups`, `group-create`, `group-rename`, `group-delete`, `group-add` and `group-remove`. The panel's group menus open only on a real right-click and a group's name is typed, so these are the first driver actions that send input: all of it lives in one native class, `PanelInput` (a right click at the pointer, Unicode text, Ctrl+A, Enter, Escape, and bringing VS Code to the front), used only from the group functions, each behind its own check (a right click only while VS Code is in front, no menu is open and the pointer is on the target where the driver put it; typing only while the keyboard focus is the group's name field, and Enter only when it shows exactly the name; Escape only while a context menu is seen open). A run waits for his 120-second idle time, takes the pointer and keyboard focus for a few seconds, and puts the pointer, an open menu and the foreground back; it refuses before touching anything (exit 5) when the request cannot be done, and checks the outcome from a fresh read of the list. `delete` of a group that holds chats needs `--force`; the chat does not have to be idle for `add` and `remove`. `list` gains a `group` field per chat. `af session start --group` no longer passes a group id to the bridge (that left the chat in Ungrouped): it reads the groups, refuses an unknown name before any chat is started, starts the chat, then places it with `group add`, and if that fails says the chat was started, gives its id and the retry command, and exits with the add's code. The `state.vscdb` group reader, `resolve_group`'s id lookup and the driver's `-GroupId` are gone.
- The panel lock is taken after the wait for him, not before. A run now waits for his idle time and the chat's records without the lock, takes the lock, checks those guards once more and goes back to waiting (lock released) if one fails, so one waiting run no longer makes every other chat's panel command wait or give up. `list` of a minimized window does the same.
- The panel driver no longer claims it never takes the foreground. Opening a chat's tab or pressing a panel button makes VS Code take the keyboard focus for the few seconds of the run. At the end of a run, after an archive's z-order undo and before the window is minimized again, the driver hands the foreground back to the window that had it when the screen work began, once, when VS Code has it and he has not touched the computer; if that fails the run says `VS Code was left in front`.

- `af session archive [<name>] [--session-id <id>]` archives a chat in the panel's list through a new driver action, `archive -Session <id>`: the chat's open tab is closed first (when it has one and no draft), the pointer rests on the chat's row (its `Archive session` button exists only while it does; nothing is clicked or typed), the button is invoked, the row is confirmed gone and the pointer goes back if it is still where the driver put it. If another window covers the row, VS Code is raised above it without keyboard focus and put back afterwards (never left always-on-top); all waiting (idle, a full-screen window in front) happens before the raise and nothing waits after it, so he cannot be left with VS Code over his work. Just before the button is invoked the chat is read again (no live record, not running, not the active row) and he must not have come back. A chat he has in front is never archived (the run refuses at once with exit 3 and the caller tries again later). The registry row is not changed, and the calling chat is refused. A missing row exits 0 worded as what is known (it may be in a collapsed group), and an unreadable sessions list is exit 2.
- `af session compact --cancel <name>` stops a queued `--when-idle` compaction. The waiter, its lock wait and its driver run (`-CancelFile`, exit 7) look for a cancel marker while they only wait; once the driver has begun changing the panel it does not cancel, and the verb says so. A cancelled job runs no `--then-file` step and is not shown to a chat as a failure; `--when-idle` prints the cancel command. A cancelled run no longer waits for him at the end, and `--cancel` says what is known when the processes are still running after 20 seconds.
- The panel driver never takes the foreground: a minimized VS Code is restored behind his window (bottom of the stack, shown without activation, placed behind his foreground window) and minimized again without activation, keeping a maximized window maximized (it comes back maximized; its placement is saved and put back with showCmd 7), never placing it behind an always-on-top window and never leaving it in the always-on-top band; the raise for archive is undone to exactly the window order it had (the first real window above VS Code is recorded, skipping hidden, cloaked and owned windows, and the result is checked against the row's centre with a fallback and a note, except when the covering window is always-on-top or VS Code is his foreground window), and each clean-up step runs even when one before it throws. At the end it is minimized again only when VS Code is not his foreground window and he is idle or another window covers it; if he has VS Code in front it is always left open. The Window pattern's restore took the foreground and reset the last-input time, which restarted every idle wait. The close retry restores a window that was minimized again, reveals the chat only when its tab or row was not the active one, waits 2 seconds between tries, and every wait writes `waiting: <reason>` to `claude-panel.log` once per change of reason.

- The panel driver's third review. Whether the chat's tab is open comes from the bridge's tab list, never from its process, which outlives the tab for a while: a closed tab whose process still runs is reported as such, an unreadable list as unknown, and his tab is opened again only once the process has ended (else a note gives the reveal command). With Send disabled, a value the driver does not recognise is reported by its length as possibly an unknown placeholder, not as his draft. A `--when-idle` waiter cuts every stage to end by the time its job expires at. The closed-route compaction waits up to 10 minutes for the panel lock (a waiter: the rest of its wait) and names the holder when it refuses.
- The panel driver's second review. After a failed send it waits for the chat's process to end on a budget of its own, opens his tab again on every path where it is closed, and builds the message's final state from a fresh read (the chat's process, the bridge's tab list, the input), never from what it did. Empty means the input's value reads blank or as the page's placeholder, not only that Send is disabled. A bridge `open` or `close-tab` that gets no answer counts as attempted and the tab list is read again. A post-send close needs a tab the driver opened in this run, still run by the process its open started. Locks and waiter jobs record the process start time, so a reused pid holds nothing, and a waiter job also expires after its wait plus a margin; two `--when-idle` calls at once start one waiter. The closed-route compaction holds the panel lock for its whole run. `af session panel` stops at 90 seconds. Bridge 0.2.0 `close-tab` checks the tab is still active right before it closes. A failed waiter's line goes to the chat that queued it.
- The panel driver closes a tab only right after one unbroken check (window, a unique and active tab, the only active row and idle, every live record `status: idle`, an empty input with Send disabled, the operator still idle) and never closes a tab it did not open in this run without it; it opens a tab only when that adds one, and stops otherwise. One run at a time holds `system/logs/panel-bridge/driver.lock`, which also keeps `af session compact` off the closed route for that chat. Every message says what the driver changed and the tab's final state; exit 3, 4 and 5 mean nothing was sent, a confirmed send exits 0 with any later cleanup failure as a note, and every `af` verb prints the driver's notes. The Send it invokes is the one it verified. One deadline bounds every step and the restore; `af` kills it at that deadline plus 60 seconds, logs the kill and says to look at the chat. A chat held by a terminal is refused. Model names match whole (`Opus 5` is not `Opus 5.5`). `--when-idle` keeps one waiter per chat, picks its route when it fires, skips a chat compacted since it was queued, and a failure is shown to the chat once. `close-untitled` needs an idle record older than 60 seconds and the lock; `/rename` titles are not logged. The bridge source is 0.2.0: `group-pick` is gone and `close-tab` closes one tab unless `all: true`; the installed 0.1.0 still has `group-pick`, which the driver never sends, and 0.2.0 goes in when no chat is running (see `system/vscode-bridge/README.md`).
- The Claude panel driver, version 2: no key events, no mouse events, no clipboard. `system/tools/claude_panel.ps1` manages chats in the Claude Code panel of the VS Code window whose title holds the vault folder name (`list`, `send`, `new`, `model`, `close-untitled`, `selftest`) through UI Automation patterns (read, Invoke, ExpandCollapse, SelectionItem, Window) and the new AgentFrame bridge extension, `system/vscode-bridge/` (installed once with `code --install-extension`; an update of an installed bridge needs an extension host restart, so do it when no chat is running), which closes, reveals and opens chat tabs and prefills a new chat's input from a file inbox under `system/logs/panel-bridge/`. A send closes the chat's tab (after proving through the tab list and the panel that the label is unique and the tab is the active one, and that the input holds no draft), opens it again with the text, reads the input back, and only then invokes `Send message`; a text starting with `/` is sent as it is, with no leading space. Guards: the operator idle for 120 seconds before every screen change and again right before Send, the chat idle by its row and its session record (the tab of a busy chat is never closed), the read-back equal to the text, and the transcript confirming the user line (or a slash command's effect) before exit 0. A minimized window is restored with the Window pattern and minimized again, and his previous chat is put back. Every model pick saves the global `model` key and the settings file's hash, writes the key back right after the pick and exits 6 if the file does not match; `new` and `af session start` require `--model` and send nothing before the picker shows it. `af session compact` compacts a running chat through it and checks for the `compact_boundary` line; `--when-idle` starts a detached waiter that compacts the chat once it finishes its turn and logs the outcome to `system/logs/panel-waiters.log`; `--then-file` sends a file as the chat's next message after a confirmed compaction. New: `af session rename`, `af session start --brief-prompt-file --model [--group <name>]` (the group name is resolved from the extension's stored groups, read only, and an unknown one is refused with the list), `af session panel`. The hard context nudge tells a build chat to run `af session compact <name> --when-idle`. `AF_PANEL_DRIVER` names another driver program (tests use a stub); `selftest` runs the whole path on a Haiku 5.5 chat it creates and is run by hand. `system/tools/panel_bridge.py` is a small client for the bridge.
- A partial loop watch no longer fails the batch run. `loop_watch.py` exits 3 when every failure is one loop's own and at least one loop was checked cleanly, and still exits 1 when the run stopped early, the raw email cleanup failed, the report could not be written, or every loop failed. A morning step that exits 3 is recorded as `partial (exit 3)` with its footer and a note pointing at the step's own report, and it is not a failure, so "AgentFrame batch" stops showing as failed in Task Scheduler on mornings when a loop or two failed validation. The loop watch's `af open due` call now times out after 60 seconds and a hung `af` is a whole-run failure.
- `af hook post-tool-use` no longer nudges on a stale number right after a compaction. When a `compact_boundary` line comes after the last main-chain assistant line, the chat's size is unknown: no nudge fires and `af session context` says the size is unknown until the next reply. Nothing changes when there is no boundary or a reply follows it.
- `af session list` and `af session reach` no longer call a roster-listed chat closed when its entry has no status (claude prints none when it is not busy, shell, idle or waiting): list says `unknown`, reach says the state is unknown, and a `shell` status counts as busy. A roster status af does not know is unknown too, so a later claude release's new status never reads as closed. `af session compact` on a chat already compacted since its last reply prints `already compact` (and that `--force` runs it anyway) and runs nothing, `--dry-run` included, instead of failing on a missing boundary; `--force` compacts it. A morning step's exit 3 is partial only for a step with its own report (the loop watch); from any other step it is a failure.
- `af watch` is a queue of timed and conditional checks any chat can add to: a date, a loop closing or staying open, a file appearing or changing, or an email a model proves. One scheduled task, `AgentFrame batch`, runs `system/tools/watch_batch.py` at 10:00, 15:00 and 19:00: it sweeps expired items into loops, checks the rest, and for each one met raises a loop and sends one phone message. Email conditions go to a locked-down Haiku call, one item at a time, and the runner validates the answer in code against what the call fetched before acting; a failure is retried once on Sonnet. The 10:00 run also does the morning jobs once a day (bills watch, loop watch, loop sweep, then the loop push, which carries the watch lines first), so the four tasks that ran them are retired: `timers.ps1 -Register` or `-Unregister` removes them, and `register-watch-batch.ps1` registers the batch task. The phone path needs `REMINDERS_DISCORD_CHANNEL_ID`; without it the run still checks and raises loops. `notify.py --test` sends a test line; model ids live in `system/models.json`.
- `af session compact <name>` compacts a closed chat from outside it with `claude -p "/compact" --resume`, summarising on the chat's own model (the `[1m]` form from the last reply's `requestedModel`) and checking the transcript gained a `compact_boundary` line. It fails closed: any roster entry for the chat, a `sessions/*.json` record naming it, or no roster refuses it, and it checks again after the run and exits 1 if the chat went live meanwhile. It also refuses a transcript under 50k tokens and a haiku summary unless `--force`; `--dry-run` prints the command. A run past 15 minutes is stopped with its child processes (Windows) and the transcript reported. `AF_CLAUDE_BIN` names another `claude` program, and git and `claude` share one process runner with a deadline.
- Session classes. A chat is `main` (350k window), `side` (300k) or `build` (1M), by default from its name (`af-main` main, `life/*` and `worker/*` side, `project/*` and `system/*` build) and overridden by a `class:` line in its brief, which `af session register --class` writes; `af session list` shows it. `af hook post-tool-use` now runs after every tool, measures the chat's context from its transcript, and nudges a build chat once at 400k tokens and at 600k (again every 50k above it), re-arming after a compaction (`af hook post-compact`); parallel tool calls claim each firing with a marker file, so it is said once. `af hook pre-compact` prints the chat's standing summary instructions at every compaction, and `af session context [name]` shows a chat's class, context, thresholds and the auto-compact window that applies. The Stop hook and `af session stop` say whether a handoff is missing, lacks `written:`, or is stale, and `af doctor` flags a brief whose `class:` is not one of the three. MIGRATION: a brief's `window:` line is no longer read; `class:` is.
- One machine. `af save` commits the private layer (`workspace/`, its own local git repo) at every stop and on request; it never fetches, pulls, merges or pushes, and skips with one line when git holds a lock or a merge is in progress. `af sync`, the hub folder, the per-message hook, the laptop kit, and `library/process/sync.md` are gone. `af doctor` flags any remote on `workspace/.git` and names the command that removes it. `system/tools/laptop/timers.ps1` is now `system/tools/timers.ps1`.
- `af needs` keeps one list of what main needs the operator to decide, in `workspace/life/needs.md`: a generated view of marked loops in `open.md`, each linking a full detail file, split into Now, Do, and Later. Every reply to him ends with one line naming how many need him now, in place of re-raising due loops.
- One chat. No rule reserves a tool or work for one chat; each does its job and routes the rest to main. `af session reach` says what a message would meet and checks it arrived, because `SendMessage` answers success for a message that is then held. Workers start with `claude -p`, and their exit wakes the chat that started them.
- `af place`, `af person`, and `af backlog ready` are new buttons. `af ready` lifts a head's `## Ship` region into `post-FINAL.md`, a deferred ingredient counts as finished, a post row can override the manifest, and a published record stays published. `af draft --file` registers a head written first.
- A weekly backlog pass (`system/tools/backlog-pass.ps1`) raises a loop naming the ready rows for main to dispatch to a reviewed builder.

- Removed retros, the feedback log and `af feedback`, technical-build, the project-mgmt governance templates, the consolidate skill, the audit database, and every `evolution.md`. The harvests at ready and publish carry the learning, button runs log to `system/logs/af-runs.jsonl`, and friction goes to `system/backlog.md`.

## v0.1.0 — a context workspace for any kind of work

First public cut of the rebuilt, domain-neutral AgentFrame. It's what I use day to day, it's still moving, and it's free to fork. Works with Claude Code, Codex, Cursor, VS Code, Antigravity, or anything else that reads files.

- **Context that survives the chat.** A fresh agent reconstructs a project from disk after a compaction, provider switch, or a month away; `sources/` and `knowledge/` stay separate, with a consolidation pass to archive resolved detail; the persona → project → flow → process chain loads only what the step needs.
- **A domain-neutral core with packs on top.** The project is the smallest unit of work, generic enough for a frontier model to scaffold for almost anything. Marketing, project management, and careers ship today.
- **A voice system trained on your real edits.** It learns from the gap between its draft and your rewrite, using reusable registers selected independently from channel and folding manual edits back in as contrastive pairs.
- **Deterministic state and a real audit trail.** `af` owns creation, versioning, locking, publishing, and doctor checks; every deliverable keeps a version trail with immutable snapshots and tracked exports; an append-only audit database records system changes.
- **Managed automations for standing work.** A project defines a job, receives queued tasks, and runs them through a bounded local agent that reports back `done`, `blocked`, or `failed`. Early — just started running on real work.
- **A Workspace Dashboard rendered from the files.** Projects, an attention list, calendar and timeline views, a preview workspace, and a read-only Automations pulse, all read straight from the same files the agents use — no second database, no model call.
- **Learn from finished work.** Closeout harvests compare drafts with manual edits and logged friction, then propose template, process, and voice-corpus changes behind a short human review; bounded runs name their goal, evidence, budget, and review points before starting.
