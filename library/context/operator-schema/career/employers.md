# Employers (schema)

One file per employment relationship under `library/context/operator/career/employers/{slug}.md`. Use a compiled-truth header plus a dated, append-only timeline, mirroring people pages: resynthesize the header when the timeline outruns it. This is the "how do I get promoted here" substrate for a career session; the evidence stays in the bank.

```markdown
# {Employer} - {current title} (since {Month YYYY})

## Now (compiled truth)
- Level & target: {current level} -> {target level}; next cycle: {Month YYYY}
- Leveling rubric: {criteria summary, per criterion: what the level requires} (source: {link/doc})
- KPIs / KPOs: {the measures that matter this cycle, each with its target}
- Manager: [[{people-page slug}]]; Coach: [[{people-page slug}]]
- Expectations in force: {what leadership has actually said is required}

## Timeline (append-only, dated)
- {YYYY-MM-DD} - {cycle event, stated expectation, rubric change, level result}
```

Promotion-case evidence mapping belongs in that case's jd-map, not here. When employment ends, retain the file as history for references and future negotiations.
