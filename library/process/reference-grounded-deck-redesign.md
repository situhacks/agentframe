# Reference-Grounded Deck Redesign

## Purpose

Preserve an existing PowerPoint's slide geometry and native object structure while applying named redesign deltas. The source PPTX is the working substrate; PPT Master rebuilds only slides whose object topology must change.

## When To Load

Load after [`deck-production.md`](deck-production.md) when an existing PPTX is the visual reference and the requested result should retain its page count, page order, layout, or intricate diagrams except for explicit changes. Do not use this procedure when the source deck is merely content for a new story.

## Procedure

### 1. Scaffold the preservation contract

Keep the operator's source untouched. Create a reference copy, working copy, and preserve-by-default manifest:

```powershell
py -3 system/tools/reference_deck.py scaffold "<source.pptx>" "<deck-project>"
powershell -File system/tools/reference_deck_com.ps1 render `
  -Deck "<deck-project>/reference/source.pptx" `
  -OutputDir "<deck-project>/reference_origin"
```

The manifest is `<deck-project>/reference-redesign.json`. It has one ordered row per source slide and exactly three modes:

| Mode | Use when | Execution |
|---|---|---|
| `preserve` | No delta | Leave the source slide untouched. |
| `native` | Text, color, font, fill, line, image, or allowlisted coordinate changes; object topology stays intact | Edit the working PPTX through the native PPTX path. Style changes need no allowlist. List every shape ID permitted to change text or geometry. |
| `rebuild` | Shapes, connectors, grouping, or layout topology must change | Rebuild this slide alone through PPT Master from its origin PNG and source-derived SVG/shape facts. Do not batch complex rebuilds into a full-deck generation run. |

Write each delta in the row's `delta`. Change a slide from `preserve` only when that row names the intended change. Keep the source render visible during a rebuild; the delta is the only license to diverge.

### 2. Execute native slides first

Apply `native` edits to a copy of `working/working.pptx` using `system/skills/pptx/SKILL.md`. Preserve shape IDs. Adding or deleting objects is a rebuild, not a native edit.

For a `rebuild` slide, isolate only that page. Start from the source-derived SVG when an unedited PPTX → SVG → PPTX round trip renders faithfully; otherwise author against the origin PNG and retain any complex native group that does not need to change. Export with notes off and paragraph merging disabled.

Replace the source slide through PowerPoint so package relationships and source formatting are resolved natively:

```powershell
powershell -File system/tools/reference_deck_com.ps1 replace `
  -InputDeck "<current-working.pptx>" `
  -OutputDeck "<next-working.pptx>" `
  -TargetSlide 6 `
  -ReplacementDeck "<single-slide-rebuild.pptx>" `
  -ReplacementSlide 1
```

Each replacement writes a new file. Previously approved slides are never regenerated by a later full-deck pass.

### 3. Verify before visual QA

```powershell
py -3 system/tools/reference_deck.py verify `
  "<deck-project>/reference/source.pptx" `
  "<candidate.pptx>" `
  "<deck-project>/reference-redesign.json" `
  --report "<deck-project>/reference-verification.json"
```

The verifier blocks:

- any change to a `preserve` slide;
- added/deleted native objects, unapproved geometry moves, or unapproved text changes on a `native` slide;
- source text disappearing from a `rebuild` slide unless its source shape ID is explicitly exempted.

After it passes, render the candidate and compare every slide against `reference_origin/`. Fix visible drift and re-run both checks. Structural verification does not replace visual review.

## Verification Or Logging

Keep `reference-redesign.json`, `reference-verification.json`, origin renders, and the final comparison sheet with the deck-production project. Promote only a candidate that passes the structural verifier and a complete origin-versus-output visual review.

## Boundaries

- This v1 procedure is a 1:1 redesign path. Add, drop, split, merge, or reorder slides through the existing deck-production route after the preservation pass.
- It does not change vendored PPT Master behavior. AgentFrame owns the source clone, manifest, isolation, replacement, and verification contract.
- If PowerPoint COM is unavailable, perform the same single-slide replacement manually in PowerPoint; do not fall back to regenerating the full deck.
- Pixel/SSIM scoring is optional triage, not the acceptance gate; intended brand changes can create large pixel differences without geometry drift.
